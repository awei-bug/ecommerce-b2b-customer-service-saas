# 2 周私有化内测冲刺清单

> 日期：2026-07-20  
> 目标：**1～3 家真实小店内测 14 天**，人工确认收款，不做公开 SaaS、不上真微信商户。  
> 成功标准见文末；与 [`完整电商标准产品架构.md`](./完整电商标准产品架构.md) 的 L0/L1 对齐。

---

## 0. 内测边界（先写死）

| 做 | 不做 |
|----|------|
| 私有化 / 你运维的一台环境 | 公开注册、自动开通收费 |
| 人工收款：付款指引 + 店长「标记已付款」 | 宣传「已支持微信支付自动扣款」 |
| 1～3 家店、小流量 | 大促、分销、复杂营销 |
| 电脑端商户后台 + C 端商城 | 小程序、App |
| 每日备份与简单监控 | 多机高可用、微服务 |

**对外话术：**

> 本系统为店铺经营试用版：顾客下单后按页面指引转账并备注订单号，店长确认到账后发货。

---

## 1. 两周日程总览

| 周次 | 主题 | 出口 |
|------|------|------|
| **第 1 周** | 生产最小可用 + 收款话术 + C 端少翻车 | 一台可 HTTPS 访问的环境；完整下单→确认收款→发货跑通 |
| **第 2 周** | 真实店铺试跑 + 修阻断问题 | ≥1 家店连续用 ≥7 天；阻断 Bug 清单清空 |

## 2. 第 1 周（Day 1–7）可勾选任务

### Day 1–2：生产最小包

> **仓库已落地：** 详见 [`deploy/day1_checklist.md`](../deploy/day1_checklist.md)  
> 含：`.env.prod.example`、Compose、Nginx、`build_frontends.sh`、`healthcheck.sh`、`win/start_api_prod.bat`、生产 `wsgi.py` 弱密钥校验。

- [ ] 复制并编辑 `deploy/.env.prod`（强 `SECRET_KEY` / DB / `PLATFORM_BOOTSTRAP_KEY`）
- [ ] 确认 `ALLOW_MOCK_PAY=0`、`SMS_DEV_MODE=0`、`FLASK_CONFIG=product`
- [ ] 本机类生产 API：`deploy\win\start_api_prod.bat` 或 Linux Gunicorn
- [ ] `bash deploy/build_frontends.sh` 产出 dist
- [ ] （推荐）`docker compose -f deploy/docker-compose.yml --env-file deploy/.env.prod up -d --build`
- [ ] 探活：`bash deploy/healthcheck.sh`；浏览器打开 mall + `/admin/`
- [ ] 域名解析到服务器；申请 HTTPS 证书（Let’s Encrypt 等）— 可延到 Day2
- [ ] Nginx 反代路径已覆盖 `/dashboard` `/payments` 与业务前缀
- [ ] 进程守护：Compose `restart: unless-stopped` 或 systemd
- [ ] 健康检查：`GET /health/` / `GET /healthz`

### Day 2–3：数据与备份 + HTTPS / 守护

> **仓库已落地：** [`deploy/day2_checklist.md`](../deploy/day2_checklist.md)  
> 含：`backup_mysql.sh` / `backup_all.sh`、`win/backup_mysql.bat`、`win/restore_mysql_test.bat`、HTTPS 样例更新、`systemd` 样例。

- [ ] MySQL 仅内网/本机访问，改掉默认弱密码（生产）
- [ ] 执行备份：`deploy\win\backup_mysql.bat` 或 `bash deploy/backup_all.sh`
- [ ] 恢复演练到临时库 `flask_shop_restore_test`（见 Day2 清单）
- [ ] 上传目录一并备份（`backup_all.sh`）或注明暂无
- [ ] 定时任务：cron 或「任务计划程序」
- [ ] HTTPS：证书 + `default.ssl.conf.example`，或书面接受本周仅 HTTP
- [ ] 进程守护：Compose `restart` / systemd 样例 / Windows 任务计划
- [ ] 记录 RPO=24h、RTO=4h

**Day 2–3 验收：** 备份文件存在且能还原出租户与订单；守护策略明确。

### Day 4：收款流程固化（无商户号）

- [ ] 每家店在「店铺设置」填好：**付款指引 + 联系电话**
- [ ] 确认 C 端下单后结果页展示付款指引
- [ ] 店长路径演练：待支付 → **标记已付款** → 待发货 → 发货
- [ ] 使用「对账导出」拉近 30 天流水，Excel 能打开
- [ ] 全站文案检查：无「微信支付自动到账」等误导表述
- [ ] 生产关闭演示下单 / 模拟支付入口（或仅管理员可见）

**Day 4 验收：** 用真实手机走通一笔「转账备注订单号 → 后台确认 → 发货」。

### Day 5：C 端少翻车

- [ ] 商品有 SKU 时，详情页必须能选规格再买（若未做完则优先补）
- [ ] 列表/详情/下单失败有明确中文错误（库存不足、停业、未登录）
- [ ] 空态：无商品、无订单
- [ ] 登录验证码：生产接短信或明确「内测固定码仅测试店」
- [ ] 租户进入方式固定：`?tenant=slug` 或子路径，写进给店主的一页说明

**Day 5 验收：** 新用户按说明 10 分钟内能下单，不靠你口头指导超过 3 次。

### Day 6：安全与权限

- [ ] 默认演示密码全部改掉；给店主独立强密码
- [ ] 按角色建账号：老板 / 仓管（只发货）/ 客服（售后）
- [ ] 用仓管账号验证：不能进员工、不能乱退款
- [ ] 上传目录不可执行；限制图片类型与大小
- [ ] CORS 仅允许你的前台域名
- [ ] 抽查审计日志：登录、标记付款、发货有记录

**Day 6 验收：** 越权接口返回 403；关键操作可在审计中查到。

### Day 7：内测包与培训

- [ ] 一页纸《店长操作手册》：登录、上架、改价、确认收款、发货、导出
- [ ] 一页纸《顾客怎么买》：打开链接、登录、下单、按指引付款
- [ ] 开通 1 个正式试运营租户（不要用 demo 脏数据）
- [ ] 预置 5～10 个真实在售商品 + 运费模板
- [ ] 约定内测群（微信群）：问题截图 + 订单号反馈

**第 1 周出口验收：**

1. HTTPS 可访问后台 + 商城  
2. 完整业务链跑通（人工收款）  
3. 每日备份成功  
4. 手册齐套，可交给非技术店主

## 3. 第 2 周（Day 8–14）可勾选任务

### Day 8–9：真实店铺接入

- [ ] 选定 ≥1 家愿意试的店（最好日单量不大）
- [ ] 开通租户、改品牌名/电话/付款指引
- [ ] 店主自己完成：上架 1 个商品、改库存、处理 1 笔测试单
- [ ] 记录卡点（登录、图片、发货、不会标记付款等）

### Day 10–11：只修阻断项

按优先级只修：

1. 不能登录 / 不能下单 / 串店数据  
2. 库存错、重复确认付款  
3. 发货后状态不对  
4. 导出打不开、金额对不上  

- [ ] 建立《阻断 Bug 列表》，修完一项勾一项  
- [ ] 非阻断（样式、文案）一律排期，不进本周

### Day 12：运营观察

- [ ] 看工作台 KPI：今日单量、待发货、待支付是否正常
- [ ] 抽 3 笔订单对账：下单金额 = 转账金额 = 导出记录
- [ ] 低库存商品是否提醒得到

### Day 13：稳定性小抄

- [ ] 写《挂了怎么办》：重启后端命令、看日志路径、联系你
- [ ] 磁盘与日志轮转（避免日志把盘写满）
- [ ] 确认 mock 支付在生产关闭

### Day 14：复盘与去留

- [ ] 店主访谈 5 问：每天用吗？最烦哪步？愿不愿继续？差啥必做？能接受付费吗？
- [ ] 统计：下单数、完成发货数、售后数、你介入次数
- [ ] 决策三选一：
  - [ ] **继续内测**（再扩 1～2 家）
  - [ ] **补主体做真支付**（进入正规收款）
  - [ ] **收缩范围**（只做后台履约，不碰 C 端获客）

**第 2 周出口验收（成功标准）：**

| # | 标准 | 达成 |
|---|------|------|
| 1 | ≥1 家非演示租户真实在用 | ☐ |
| 2 | 连续 ≥7 天有后台登录或订单处理 | ☐ |
| 3 | 至少 5 笔真实闭环（下单→确认收款→发货） | ☐ |
| 4 | 无未修的「串租户 / 不能下单 / 钱货状态错」 | ☐ |
| 5 | 店主能按手册独立操作，不依赖你实时盯盘 | ☐ |

## 4. 技术部署清单（命令级备忘）

> 具体域名与路径按你机器改。

```bat
:: 后端（服务器）
cd flask_shop
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install gunicorn   :: Linux
:: Windows 可用 waitress: pip install waitress

:: 迁移与种子（新库）
python scripts\migrate_l1_features.py
python scripts\migrate_sku.py
python scripts\seed_tenants.py
python scripts\seed_rbac_roles.py --with-users
python scripts\reset_demo_passwords.py

:: 前端构建
cd vue_shop && npm ci && npm run build
cd mall && npm ci && npm run build
```

**Nginx 要点：**

- 静态：`vue_shop/dist`、`mall/dist`
- API：反代到 `127.0.0.1:5000`
- 上传目录只读静态映射，禁止 PHP/脚本执行
- 强制 HTTPS

**生产 `.env` 必查：**

```env
FLASK_ENV=product   # 或你们 ProductionConfig 对应名
SECRET_KEY=...      # 长随机
ALLOW_MOCK_PAY=0
PAY_DEFAULT_CHANNEL=mock
MYSQL_...=...
PLATFORM_BOOTSTRAP_KEY=...
```

## 5. 内测店主最小权限包

| 账号建议 | 权限焦点 |
|----------|----------|
| 老板 | 全权 + 导出 + 标记付款 |

开通后立刻：**改密码、关演示账号对外分享。**

## 7. 每日站会（给你自己）

1. 今天有没有新的**阻断**问题？  
2. 真实订单有没有跑通？  
3. 备份今天成功了吗？
