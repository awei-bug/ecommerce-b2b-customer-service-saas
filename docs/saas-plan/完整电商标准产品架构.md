# 完整电商项目 · 标准产品架构（通用模板）

> 版本：v1.0 · 2026-07-18  
> 定位：**可直接落地的通用架构蓝图**（模块边界、能力清单、数据域、阶段裁剪），不是「一次性全部开发完成」。  
> 与现状关系：本仓库已有 **多租户 Spike + 商户后台骨架 + C 端成交路径雏形**；下文标明 **已有 / 可演进 / 远期**。

---

## 0. 一句话产品定义

**多租户电商操作系统：**  
买家在 C 端完成「找货 → 信任决策 → 下单支付 → 履约售后」；  
商家在 B 端完成「开店上架 → 获客转化 → 发货售后 → 资金对账」；  
平台在中台完成「入驻审核 → 风控治理 → 活动与仲裁」；  
履约与数据风控作为横切能力支撑全链路。

**适用模板场景（默认）：** 国内自营/入驻型综合或垂直电商（标品为主），可裁剪为：品牌自营、多商户商城、本地生活（需替换履约域）。

## 1. 五域总览（标准拆分）

```text
┌─────────────────────────────────────────────────────────────────┐
│                     接入层（Web / H5 / 小程序 / App）              │
└─────────────────────────────────────────────────────────────────┘
        │                │                │
        ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ 1.C 端用户商城 │ │ 2.B 端商家后台 │ │ 3.运营管理中台 │
│  Buyer App   │ │ Merchant Ops │ │ Platform Ops │
└──────────────┘ └──────────────┘ └──────────────┘
        │                │                │
        └────────────────┼────────────────┘
                         ▼
              ┌─────────────────────┐
              │   业务中台 API 层     │
              │ 商品/交易/会员/营销…  │
              └─────────────────────┘
                    │           │
         ┌──────────┘           └──────────┐
         ▼                                 ▼
┌─────────────────┐              ┌─────────────────┐
│ 4.履约物流系统    │              │ 5.数据风控系统    │
│ Fulfillment     │              │ Risk & Analytics │
└─────────────────┘              └─────────────────┘
         │                                 │
         └──────────────┬──────────────────┘
                        ▼
         支付 / 短信 / OSS / 快递 / 消息 等外部能力
```

| 模块 | 服务对象 | 核心价值 | 本仓库现状 |
|------|----------|----------|------------|
| **1 C 端** | 买家 | 找得到、信得过、买得顺、售后省心 | 电脑端路径雏形（列表/详情/确认/支付结果/订单）+ 登录 API |
| **2 B 端** | 商家员工 | 开得了店、卖得出货、发得了货、算得清账 | 商户后台骨架 + 商品/订单/角色菜单 |
| **3 运营中台** | 平台运营 | 管得住商家与内容、处得了纠纷 | **基本没有** |
| **4 履约物流** | 商家/平台/买家 | 发得出、追得到、退得回 | 仅物流字段/时间线雏形 |
| **5 数据风控** | 平台/商家 | 防刷单假货、可运营可决策 | **基本没有** |

**横切基础（必须先于花活）：** 多租户隔离、统一身份（买家/商家员工/平台运营三套）、支付单与订单状态机、配置与密钥、审计日志、部署运维。  
本仓库横切：**租户隔离、商户 JWT、买家 JWT、订单状态机、支付单/mock、库存 CAS** 已部分具备。

## 2. 模块 1：C 端用户商城（Buyer）

### 2.1 目标用户旅程（标准）

```text
进店/频道 → 搜索分类/推荐 → 详情建立信任 → 登录 → 下单支付
  → 物流跟踪 → 确认收货/评价 → 售后 → 会员复购
```

### 2.2 能力地图（标准产品级）

#### A. 首页（找货难、决策难）

| 能力 | 标准要求 | 落地优先级 |
|------|----------|------------|
| 分类树 + 关键词搜索 | 必做 | **P0** |
| 图片搜 / 语音搜 / 同款比价 | 增强 | P2 |
| 内容种草（短视频/图文/问答） | 内容中台 | P2 |
| 评价可信（禁刷评 + 风控） | 依赖模块 5 | P1 起规则，P2 算法 |
| 分层推荐（新人/复购/榜单） | 推荐服务 | P1 规则推荐 → P2 算法 |
| 优惠透明（券叠加、满减试算） | 营销计价 | P1 |

#### B. 商详（信任、踩坑）

| 能力 | 标准要求 | 优先级 |
|------|----------|--------|
| 标准化参数模板（类目属性） | 必做 | P0（先类目属性，后强模板） |
| 实拍/追评/差评不隐藏 | 必做 | P1 |
| 售后保障标签可视化 | 必做 | P1 |
| 商家资质公示 | 合规 | P1 |

#### C. 交易链路（下单、售后）

| 能力 | 标准要求 | 优先级 |
|------|----------|--------|
| 登录（手机/微信） | 必做 | **P0（手机验证码已有骨架）** |
| 地址簿 + 确认订单 | 必做 | **P0（已有雏形）** |
| 微信/支付宝/分期 | 必做支付至少 1 条 | **P0 微信** → P1 支付宝 |
| 订单状态查询 | 必做 | **P0** |
| 物流轨迹 | 必做 | P1（对接快递 100 等） |
| 一键退换、上门取件、仲裁 | 售后域 | P1 仅退款 → P2 退货取件/仲裁 |

#### D. 私域会员（复购）

| 能力 | 优先级 |
|------|--------|
| 积分/等级/专属价 | P2 |
| 消耗品复购提醒 | P2 |
| 关注店铺/上新通知 | P2 |

## 9. 与「完整愿景」的裁剪原则（否则做不完）

你列出的能力 ≈ **头部电商 3～5 年 + 大团队** 的集合。标准落地必须裁剪：

| 层级 | 含义 | 包含示例 |
|------|------|----------|
| **L0 可交易** | 能开店、能卖、能收款、能发货 | 多租户、商品、订单状态机、1 支付通道、发货、基础售后 |
| **L1 可运营** | 商家愿意每天用 | 工作台、导出、券、物流轨迹、简报、2 角色以上 RBAC |
| **L2 可治理** | 平台能管很多商家 | 入驻审核、违规下架、仲裁、套餐计费 |
| **L3 可增长** | 规模化获客复购 | 推荐、内容、会员、分销、AI 工具 |
| **L4 智能化** | 算法与自动化 | 图搜、反刷单模型、智能定价建议 |

**完整架构文档描述 L0～L4；默认研发执行顺序只允许从 L0→L1→L2，L3/L4 单独立项。**

## 10. 分阶段落地路线图（通用模板）

### Phase 0 — 地基（已大部分完成 / 补齐）

- [x] 多租户 tenant_id  
- [x] 商户登录 JWT  
- [x] 买家登录骨架  
- [x] 订单状态机 + 支付单  
- [x] 库存 CAS  
- [ ] 生产部署 HTTPS + 备份  
- [ ] 操作审计  

### Phase 1 — L0 可交易（MVP 产品）

**C：** 完整购买路径 + 真微信（或支付宝一条）+ 地址 + 订单查询  
**B：** 商品上架、待发货工作台、仅退款、导出  
**不做：** 图搜语音搜、短视频、分销、AI 文案  

**验收：** 3 个真实/沙箱商家完成「上架→用户下单支付→发货」。

### Phase 2 — L1 可运营

- 运费模板、物流轨迹对接  
- 优惠券/满减计价  
- 评价（含基础反刷规则）  
- 商家工作台真实 KPI  
- 老板/店员/仓管角色  

### Phase 3 — L2 可治理（SaaS 多商户）

- 运营中台：入驻审核、冻结、仲裁  
- 套餐配额与订阅  
- 商品/内容审核流  
- 平台级配置支付与短信  

### Phase 4 — L3/L4 增长与智能

- 会员积分、推荐、内容种草  
- 秒杀拼团分销  
- 图搜/AI 上架/反刷单模型  
- 运费险、多仓、复杂供应链

## 16. 明确不在「第一期模板交付」的内容

为防止范围爆炸，**标准第一期交付包（L0）不包含：**

- 图搜、语音搜、同款比价  
- 短视频种草、AI 生成带货视频  
- 分销裂变、复杂会员  
- 运费险完整产品、多仓 WMS  
- 自研反刷单深度学习  
- 微服务拆分  

这些都在架构中 **留扩展点**，但不进 L0 排期。
